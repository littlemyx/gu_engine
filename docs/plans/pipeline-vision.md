# Конвейер: пайплайн новеллы от замысла до релиза

Дизайн-документ. Отвечает на четыре боли текущего продукта и добавляет пятое требование:

1. Бриф оторван от библиотеки ассетов — префабы применяются копированием, связь умирает в момент вставки.
2. «Иерархия истории» — свалка статусов генерации, а не структура истории.
3. Генерация — прогресс-бар `N/9`: не видно, что происходит, артефакты невидимы до конца прогона.
4. Нет цельного пайплайна «от нуля до продакшена» с возможностью подрулить в каждой точке.
5. **Превью**: эмулятор игры прямо в редакторе, на том же пайплайне, что и компилятор — как Play mode в Unity.

Документ собран из разведки кодовой базы (5 карт подсистем), трёх независимых концептов
(«инкрементальная сборка», «кинопроизводство», «диалог с режиссёром») и их адверсариальной
критики, плюс отдельная разведка встраивания движка и превью-паттернов индустрии
(Inky, Ren'Py, Harlowe, Yarn Spinner, Unity).

---

## 1. Концепция: конвейер над графом артефактов

Для автора продукт — **семь зон конвейера**, как этапы кинопроизводства: Замысел → Структура →
Проза → Медиа → Превью → Проверка → Релиз. Понятная дорога слева направо, всегда видно, где ты
и что осталось.

Под капотом — **граф артефактов**. Каждая вещь, которую произвёл пайплайн (каст-план, бит хребта,
проза юнита, спрайт, QA-отчёт, бандл), — это адресуемый артефакт со статусом, отпечатком входов,
историей вариантов и ценой. Прогресс-бар умирает; его место занимает ведомость производства.

Зоны — **не турникеты**. Автор ходит по конвейеру в обе стороны сколько угодно; зона показывает
свою готовность (сколько артефактов missing / stale / fresh) и цену «довести до готово». Гейты
существуют только перед Релизом — и они честные (см. §9).

### Пять законов

1. **Артефакт первичен и видим с рождения.** Ничего не прячется в невидимом драфте до конца
   прогона. Черновик показывается по мере генерации (механика `draft > committed` через
   `effectiveScalar/effectiveMap` уже существует — её надо подключить к derive-вьюхам, а не прятать).
2. **Платим только за missing и stale.** Правило из `calendarRunState` возводится в продуктовый
   закон: любой запуск генерации — это дифференциальная досборка, и её смета видна ДО запуска.
3. **Одна семантика.** `story_core` — единственный исполнитель правил. Превью, QA-симуляция и
   релизная игра гоняют буквально один `StoryletDirector` и один бандл одного компилятора
   `buildStoryletBundle`. Второй реализации не существует по построению.
4. **Ссылки, а не копии.** Библиотека ассетов связана с брифом кастингом по ссылке
   (`CastRef`), а не одноразовым копированием. Связь живёт в обе стороны: библиотека → роль
   и роль → библиотека (capture = publish).
5. **Подрулить можно в любой точке, но не обязательно ни в одной.** По умолчанию конвейер едет
   в режиме автопилота (всё `proposed`, авто-принято); каждая точка вмешательства — опция,
   а не обязательная приёмка. Четыре канала руления: заметка режиссёру, правка руками, lock,
   правка входа с превью последствий (§7).

## 2. Модель данных: артефакт

Единица всего в конвейере:

```ts
Artifact {
  key: ArtifactKey            // стабильный адрес: { stage, itemKey } — 'dialogue_units/enc_kaya_3'
  ownership:                  // ось 1 — кто хозяин содержимого
    | 'proposed'              //   сгенерировано, автор не смотрел (дефолт автопилота)
    | 'approved'              //   автор явно принял
    | 'authored'              //   автор правил руками — не перегенерировать без спроса
    | 'locked'                //   не трогать вообще (переживает любой каскад)
  freshness:                  // ось 2 — вычисляется, не хранится
    | 'missing' | 'fresh' | 'stale'
  fingerprint: string         // хеш честно объявленных входов (обобщение imageFingerprint)
  takes: Take[]               // история вариантов: сгенерированные попытки + ручные версии
  selectedTake: number        // какой вариант «принят» (обобщение Suno filenames[]+selected)
  notes: string[]             // заметки режиссёру — уедут в previousIssues при регенерации
  provenance: { runId, promptVersion, castRef?, cost }
}
```

**Две оси, не одна шкала.** Владение и свежесть ортогональны: `authored`-юнит, у которого
изменился бит-родитель, — одновременно `authored` и `stale`; `locked`-локация при обновлении
префаба — `locked` и `stale`. Конфликт `locked + stale` не разрешается системой — он показывается
бейджем, решает автор. `authored + stale` при «Догнать до fresh» не перегенерируется молча:
попадает в план отдельной секцией «требуют вашего решения».

**Честность отпечатков.** Граф зависимостей объявляется на уровне стадий (сегодняшний
`dirtyStages`: cast → calendar → spine → schedule → units → проза → концовки), гранулярность
до itemKey — только там, где она реальна уже сейчас: медиа по `locationHash` /
liId, проза юнита от его собственных входов. Мы **не** обещаем «правка speechPattern не трогает
расписание» — расписание глобальный солвер, честный отпечаток протухает его целиком. Правило
приоритета: лучше протухить лишнее, чем молча оставить false-fresh. Со временем гранулярность
растёт за счёт сужения входов самих промптов (build*Request перестают есть весь бриф целиком) —
это отдельная работа, меняющая качество генерации, и она делается постадийно, а не декларацией.

Состав отпечатка — явный контракт, а не «какой-то хеш»: `hash(принятые тейки
артефактов-входов + поля брифа, объявленные входами стадии + promptVersion стадии)`.
Версия промпта входит в отпечаток, но повышается **вручную** при содержательной правке
шаблона — деплой кода сам по себе не протухает проекты (иначе каждый релиз студии обнулял бы
оплаченное). Контекст соседей входит только как объявленный вход (beatText родителя — вход
прозы потомка), а не «весь стек неявно».

**Стабильность ключей.** Инкрементальность держится на том, что `itemKey` переживает
регенерацию родителя. LLM выдаёт новые beatId при перегенерации хребта — значит, у прогона
появляется обязательный шаг **reconcile**: сматчить новые биты со старыми (слот, роль в арке,
близость окон), перенести `locked/authored/notes` на совпавшие, а несматченных показать в ленте
как сирот с ручным маппингом. Это обобщение уже работающего `reconcileImagesForWorld` — с картинок
на все артефакты. Без reconcile модель статусов рассыпается на первом же `force spine`.

**Такты не выбрасываются.** Сегодня best-of retry выбрасывает проигравшие попытки, а повторный
прогон медиа перезаписывает файл. В конвейере каждая попытка — take: можно вернуться, сравнить,
«сделать этот вариант принятым». Ретеншн: последние N тейков на артефакт (настройка), остальное — GC.

## 3. Зоны конвейера

```
 0 Замысел ──→ 1 Структура ──→ 2 Проза ──→ 3 Медиа ──→ 5 Проверка ──→ 6 Релиз
      │              │             │           │             ↑
      └──────────────┴──────── 4 Превью ◄─────┴─────────────┘
                        (сквозное: доступно с зоны 1, на заглушках)
```

### Зона 0 — Замысел: бриф + кастинг-стол

Бриф перестаёт быть формой-простынёй в модалке и становится первой зоной конвейера: слева
чек-лист готовности (это `validateBrief`, отрисованный как прогресс зоны), в центре — карточки.

**Генерация брифа — реализована.** Первый живой кусок конвейера уже в продукте, и он работает
по законам §1 в малом масштабе:

- **Пробелы, а не форма целиком.** `computeBriefGaps` находит пустые поля; генератор трогает
  только их — заполненное автором неприкосновенно (закон «платим только за missing» на уровне
  зоны 0). Слияние (`mergeGeneratedBrief`) страхует дважды: пишутся только пути из списка
  пробелов, и только если поле **всё ещё пусто на момент слияния** — модель, вернувшая бриф
  целиком вместо патча, ничего не затрёт, а правка руками во время прогона не перезаписывается.
- **«Авто»-поля.** Скалярные габариты (формат, акты, длительность, плотность ветвления,
  интенсивность тона, пол/голос протагониста, профиль концовок) допускают `null` = «автор не
  задал, решит генератор»; `resolveBrief`/`resolveScale` — единственный шов, где «авто»
  превращается в конкретное значение для всей арифметики пайплайна (смета, календарные цели,
  ступени арки). `blankBrief` стал по-настоящему пустым — раньше «пусто» тихо носило дефолты
  образца, генератор считал их авторским выбором, и история всегда выходила на 4 акта / 30 минут
  независимо от заметок автора.
- **Заметки автора → директивы.** Свободный текст («свалите сюда всё: сеттинг, вайбы, обрывки
  характеров») отдельной дешёвой стадией `briefHintParse` (tier B) раскладывается в адресные
  директивы по полям каталога (`BriefDirective { target, instruction }`); каталог отдаётся
  целиком, а не только пустые поля — лучше получить директиву на заполненное и отбросить, чем
  потерять фразу автора. Это первый живой пример канала «заметка режиссёру» (§6), уже
  адресованный до поля.
- **Каталог полей — единая точка истины.** `briefFields` кормит и поиск пробелов, и целевые
  объёмы, и промпт (description-ы уезжают в LLM дословно). Ползунок «Подробность» (1–5,
  `briefVerbosity`) масштабирует целевые объёмы прозаических полей; структурные поля (токены,
  размер каста, палитра) от него не зависят — там объём это структура, а не многословие.
- **Ретраи с фидбеком.** До 3 попыток `briefFill` (tier A — вход всего пайплайна, ошибка
  тиражируется дальше); ошибки `validateBrief` уезжают в `previousIssues` следующей попытки
  (тот же транспорт best-of retry, что и в прогоне), применяется лучшая попытка по минимуму
  ошибок. Санитайз на слиянии: числа зажимаются в диапазоны, значения вне enum молча
  отбрасываются, цвета — только hex, `archetypeSpecifics` — только ключи схемы архетипа.
- **Смета до, откат после.** Кнопка показывает «≈$» до клика (`BRIEF_GEN_COST_EST`) — колл-щит
  §5 в миниатюре; стоимость каждой попытки пишется в общий счётчик проекта (`addRunCostAmount`).
  «Откатить» возвращает снимок до генерации — недеструктивность закона тейков, пока без
  истории тейков.
- **Форма и есть предпросмотр.** Никакого отдельного экрана приёмки: панель живёт над формой
  брифа, результат ложится прямо в поля, статусная строка ведёт по фазам
  (разбор заметок → заполнение → «готово, заполнено N полей — проверьте и поправьте»).

Оркестрация живёт в компоненте, не под Web Lock проекта: генерация брифа быстрая, перезагрузку
не переживает и в фоне не нужна — это осознанное исключение из правила «один оркестратор» (§5),
и при переезде зоны 0 на общий конвейер его надо будет пересмотреть. Серверные стадии
`briefHintParse`/`briefFill` — тот же batch-паттерн text_gen, что и остальные.

Сопутствующая честность гейтов уже сегодня: `briefReady` блокирует не только запуск с нуля,
но и «Продолжить черновик» / «Перегенерировать с фидбеком QA», а падение `validateBrief` на
недозаполненном брифе (например, после импорта чужого файла) превращается в ошибку зоны,
а не в падение студии.

**Кастинг-стол** — главное новое. Роли истории (протагонист, LI, мир, аудио-набор) — это слоты,
каждый заполняется одним из трёх способов:

- **Из библиотеки**: перетащить префаб на роль (не «на панель иерархии»). Возникает ссылка
  `CastRef { prefabId, version, mode: 'linked' | 'forked', overrides }`. Карточка LI в брифе —
  view поверх префаба с локальными оверрайдами-diff. Ассеты пришедшего префаба (спрайты, фоны,
  аудио) сразу ложатся артефактами зоны Медиа со статусом `locked` — они уже оплачены.
- **Сгенерировать**: роль помечается `generate`. Уже сегодня карточки LI рождаются генерацией
  брифа: пустой каст — единственный «пробел» `loveInterests`, генератор возвращает до 8 карточек
  (id присваивает редактор, не модель; карточка с неизвестным архетипом отбрасывается целиком);
  у существующих карточек дозаполняются только пустые поля, сматченные по id.
- **Руками**: пустая карточка, автор пишет сам (`authored`).

Обновление префаба в библиотеке не делает ничего молча: на роли появляется бейдж «есть v3»,
клик — diff, апгрейд — осознанное действие. Конфликт оверрайдов с diff новой версии не мержится
автоматически: показываются оба значения, автор выбирает (никакого three-way merge).

Обратный поток: с любой роли/локации/аудио — «Снять в картотеку» (capture = publish новой версии).

**Предпосылка, без которой кастинг не работает** (слепая зона всех трёх концептов): библиотека
должна хранить **иммутабельные снапшоты версий**, а не только последний payload с счётчиком.
`prefabStore` v2: `versions: Record<version, payload>` + ретеншн. И переносимость: `.guproj`
обязан нести снапшоты закастованных версий префабов — иначе файл проекта на другой машине
превращается в висячие ссылки (`gu-prefab-library` глобальна для машины и в `.guproj` не едет).
При открытии чужого `.guproj` снапшоты вливаются в локальную библиотеку как импортированные версии.

Проект **всегда держит локальный снапшот** закастованной версии (тот же, что едет в
`.guproj`): библиотека — источник обновлений, а не носитель истины проекта. Поэтому удаление
префаба из библиотеки ничего не ломает — ссылка деградирует в `forked` с бейджем
«источник удалён», проект продолжает жить на своём снапшоте.

Оговорка про аудио: аудио-набор кастится не как «роль», а как **пакет оформления** — карточка
слота = список треков с прослушиванием, оверрайды = замена/добавление отдельных треков,
diff версий = список изменённых треков. Метафора кастинга на нём заканчивается, и это нормально.

### Зона 1 — Структура: каркас бесплатно

Стадии: cast → world_calendar → spine ⇄ schedule (петля с детерминированным критиком — уже есть).
Выход зоны — одобренный каркас: биты, окна, ветки, расписание, реестр локаций.

Ключевой ход: **структурная репетиция — автоматический фон, а не кнопка**. Как только каркас
собран/изменён, в фоне бесплатно гоняются D2-проверки на `stubMissingProse`-бандле и симуляция
политик через настоящий `StoryletDirector` (весь механизм уже написан в `storyQA`). Автор живёт
в этой зоне неделю, двигает биты и ветки, и на каждое изменение видит: достижимость, мёртвые
слоты, голодающие юниты — **до того, как потратил доллар на прозу**. Превью (зона 4) уже
работает здесь же — на заглушках.

Чтобы «двигать биты и ветки» было не фигурой речи, зоне нужен **редактор каркаса**: перенос
бита между слотами, правка окон и развилок, добавление/удаление бита — с автоматической
ревалидацией детерминированным солвером schedule (петля spine ⇄ schedule уже умеет чинить
хребет по ошибкам валидатора) и фоновыми D2-проверками. Сегодняшний «Чертёж» — read-only
derive-вью; редактор — отдельная работа, и она стоит в дорожной карте (№4) явно, иначе
зона 1 остаётся витриной.

### Зона 2 — Проза: самая дорогая, поэтому самая управляемая

Стадии: beat_prose → anchor_transitions → event_pool → prune → dialogue_units → ending_prose.

- **Колл-щит перед запуском** (§6): план по позициям со сметой, а не кнопка «Пуск».
- **Порционная генерация**: юниты идут порциями с осмысленными границами (по ступени арки, по LI).
  После каждой порции — необязательный чекпоинт: конвейер продолжает сам (автопилот), но автор
  может поставить «паузу после текущей порции», посмотреть раши, оставить заметки — и порция
  перегенерируется с фидбеком до продолжения. Это отвечает на главную дыру: 80% денег тратится
  внутри одной стадии, и сегодня туда нельзя вмешаться.
- **Каскад прозы битов честен**: beat_prose последовательна (потомкам нужен beatText), поэтому
  «дубль» раннего бита протухает прозу потомков — смета это показывает, а не прячет.
- **Континуити-проверка после частичных пересборок**: если перегенерирован кусок посреди
  залоченных соседей, автоматом гоняется дешёвый LLM-линт стыков (стиль, обращения, фактические
  отсылки через границу locked/fresh). Частичная регенерация без этого — генератор стилистического дрейфа.

### Зона 3 — Медиа: дорожки того же конвейера

Фоны, спрайты, аудио — не три кнопки с эфемерным `useState`, а параллельные дорожки того же
оркестратора: те же артефакты, статусы в персистентном сторе, та же лента, тот же колл-щит.
Батч-API `image_gen` изоморфен `runBatch` — унификация обоснована кодом. При этом у медиа-дорожек
своя семантика, и она проектируется, а не «объявляется»: другой поллинг и таймауты, цепочка
«idle как референс → позы» (узел с внутренним порядком), выбор из двух Suno-вариантов — это
встроенный чекпоинт выбора тейка. Выбор тейка — в галерее (side-by-side для картинок,
A/B-прослушивание для аудио, diff для прозы).

### Зона 4 — Превью: эмулятор в редакторе (сквозная)

Подробно в §8. Здесь главное: превью — не финальная зона, а **сквозная способность**, доступная
с момента, когда есть каркас (на заглушках прозы). Кнопка ▶ живёт в тулбаре всегда.

### Зона 5 — Проверка: полный QA

Всё, что сегодня спрятано за кнопкой «Проверить историю»: D2 структурный отчёт, D3 симуляция
политик × сидов, D4 LLM-критик листьев, плюс автопрогоны с рандомными политиками и статистикой
достижимости концовок. Отчёт — артефакт с отпечатком входов: «QA свежий» значит «прогнан на
текущих отпечатках», и только это открывает релиз. D4-критик виден в ленте по батчам, его цена —
позиция колл-щита (сегодня — слепой поллинг вне сметы).

### Зона 6 — Релиз

Релиз — **иммутабельная сущность**, а не скачанный файл:

```ts
Release {
  n: number                       // порядковый номер
  bundle: StoryBundleV2           // запечённый бандл
  stats: StoryletBundleStats      // сегодня выбрасывается в строку runLog — теперь витрина
  qaReport: StoryQAStatus         // отчёт, на котором открыт гейт
  lockfile: Record<ArtifactKey, fingerprint>  // снимок отпечатков всех входов
  seed: number
}
```

Гейты честные: «QA ни разу не запускался» = закрыто (сегодня `qaErrors` пуст при
`storyQA === null` — и гейт открыт); юниты без прозы — блокер со списком, а не молчаливое
выпадание из бандла (`unitsWithoutProse` уже считается — его надо показать и заблокировать).
Из релиза: скачать `.gu.json`, собрать standalone (`build:game` — рабочий хвост остаётся как
есть), сравнить с предыдущим релизом (diff lockfile-ов = «что изменилось с v3»).

**Откат** — не перезапись рабочих сторов. Релиз хранит не только lockfile, но и снапшот
принятых тейков (в IndexedDB, §10); старый релиз всегда можно сыграть и собрать (бандл
самодостаточен), а «восстановить как черновик» возвращает его тейки в ведомость **новыми
тейками** — недеструктивно, автор принимает их как обычные варианты.

## 4. Две панели вместо «иерархии»

Диагноз всех трёх концептов совпал: текущее дерево (`derive/hierarchyModel.ts`) смешивает два
вопроса — «как устроена история?» и «что произведено и почём?». Ответ — два раздельных вью,
оба derive-only (архитектура «сторы → чистые derive → тупые вьюхи» сохраняется):

**«Пайплайн»** (производственная ведомость) — зоны конвейера с готовностью: счётчики
missing/stale/fresh, цена «довести до fresh», активные дорожки прогона. Клик по зоне —
ведомость её артефактов; клик по артефакту — инспектор (тейки, заметки, провенанс, цена).
Это ответ на «что происходит и где артефакты».

**«Структура истории»** (нарративное дерево) — только смысл: акты → слоты → биты (с ветками);
персонажи → ступени арки → сцены; локации мира. Никакого аудио-банка (ему место в доке),
никаких групп-нестатусов. Статусы производства присутствуют только бейджами на узлах
(●fresh ◐stale ○missing), клик по бейджу телепортирует в ведомость. Дерево осмысленно и ДО
генерации: показывает роли и запланированные слоты уже из брифа — пустая студия перестаёт
встречать автора пустой панелью.

Инвариант Selection → Inspector сохраняется и усиливается: любой узел любой панели открывает
инспектор с его артефактами, и в каждом инспекторе живые кнопки «Перегенерировать с заметкой» /
«Править руками» / «Lock» (сегодняшние disabled-кнопки BeatInspector/UnitInspector — первые
кандидаты на подключение).

**Словарь интерфейса — авторский, не инженерный.** В UI живут слова «не создано / устарело /
готово», «смета», «план», «дубль». Fingerprint, lockfile, itemKey — термины этого документа
и кода, автору они не показываются. По умолчанию — простой режим: «Пайплайн» — это зоны, их
готовность и одна кнопка «Продолжить конвейер»; ведомости, тейки и провенанс раскрываются
по клику, а не встречают писателя стеной. Первый запуск: новый проект открывается в зоне 0
с дорожкой «что будет дальше», а не пустыми панелями.

## 5. Генерация без чёрного ящика

Три момента времени:

**До — колл-щит.** Любой запуск начинается с dry-run плана: топо-список позиций из
dirty-каскада с пометками «из кэша, бесплатно» / «генерация ≈$0.12» / «locked, пропускаем»,
итоговая смета, галки-скоупы («только ступени 1–2», «без концовок», «до spine»). Запуск — подпись
под сметой. Пока `text_gen` не возвращает usage, все цифры честно помечены «≈» (оценка по
`STAGE_COST_EST`); контракт на фактический usage — отдельная серверная работа (§10), после неё
«≈» исчезает. Врать про деньги в меньшую сторону нельзя — грубый каскад лучше оптимистичного.
Миниатюра паттерна уже живёт в зоне 0: кнопка генерации брифа показывает «≈$» до клика
(`BRIEF_GEN_COST_EST`), а потраченное уезжает в общий счётчик проекта.

**Во время — лента.** `runLog` перестаёт быть плоскими строками и становится типизированной
шиной событий: `{ artifactKey, phase, attempt, outcome, cost, ts }` (он «уже почти такой»).
Лента — главный вид прогона: позиции плана загораются по мере готовности, клик по любой —
артефакт открывается в инспекторе **немедленно**, не дожидаясь конца прогона (раши через
`draft > committed`). Прогресс-метр считает позиции плана, а не 9 фаз. Управление: пауза на
границе вызова, стоп отдельной дорожки, «пауза после порции» (§3, зона 2).

**После — ведомость.** Артефакты не «где-то в localStorage», а в ведомости зоны: с тейками,
ценой, провенансом («рождён прогоном #12, промпт v3, по заметке „меньше пафоса"»). Прогон тоже
артефакт: журнал прогонов с итогами и стоимостью.

Транзакционность смягчается: коммит **позонный**, а не всё-или-ничего девяти стадий. Внутри
зоны — прежняя атомарность (draft копится, коммитится разом), между зонами — независимость:
успешная Структура коммитится, даже если Проза упала. Семантика reconcile фонов и сброса
QA-отчёта привязывается к коммиту зоны-владельца, не к глобальному финалу.

**Замок и вкладки.** Прогон, точечная регенерация и медиа-дорожки — один оркестратор под
одним Web Lock проекта: параллельность живёт **внутри** прогона (дорожки одного плана), а не
соревнованием независимых прогонов — «точечный дубль» из инспектора ставится в очередь того же
оркестратора. Пауза на чекпоинте **отпускает замок**: «прогон, ждущий приёмки сутки» — это не
живой процесс, а состояние стора (черновик и `pendingBatch` персистентны, реаттач после
reload уже так работает). Вторая вкладка видит ленту и ведомость read-only через
storage-события (как сейчас) и может продолжить паузу у себя, взяв замок.

## 6. Подруливание: четыре канала

1. **Заметка режиссёру.** На любом артефакте: «сделай ссору тише, без крика» → заметка уезжает
   в `previousIssues` регенерации этого артефакта (обобщение `seedIssues`/`qaSeeds` с уровня
   прогона до уровня элемента; транспорт best-of retry уже умеет фидбек — надо адресовать его
   до itemKey). Первый живой пример адресации — `briefHintParse` (§3, зона 0): свободный текст
   автора раскладывается LLM-ом в директивы `{ target, instruction }` по конкретным полям;
   тот же ход обобщается с полей брифа на артефакты конвейера.
2. **Правка руками.** Инспектор становится редактором своего артефакта; артефакт переходит
   в `authored` и не перегенерируется без спроса. Ручная правка **обязана** проходить те же
   структурные валидаторы и линты, что и генерация (циклы диалога, choice-дельты, время суток) —
   иначе руками ломается то, что чинили детерминированные починки, и это молча доедет до бандла.
   Честная оговорка: полноценный редактор графа DialogueUnit — отдельный большой продукт;
   первая итерация — правка текста реплик и вариантов при неизменной топологии.
3. **Lock.** «Это удачное — не трогать». Переживает любые каскады; конфликт со stale — бейдж.
4. **Правка входа с превью последствий.** Изменение брифа/префаба/бита после генерации
   показывает ДО применения: «протухнет проза всех 44 юнитов и концовки ≈$5.10; locked: 3 —
   не тронем; медиа переживут» — вместо сегодняшней строки-warning «правки брифа её обесценят».
   Считается из того же графа зависимостей, что и колл-щит, поэтому числа ровно настолько
   грубы, насколько груб граф (§2): при стадийной гранулярности правка карточки LI честно
   протухает всю прозу, и смета это говорит. Точечнее («переживут 30 из 44») она становится
   только по мере сужения входов промптов — обещать это раньше значит врать про деньги
   в меньшую сторону.

## 8. Превью: Play mode в студии

**Архитектурный вердикт разведки: импорт движка как библиотеки, не iframe.** Семантика уже
исполняется в клиенте (`storyQA` гоняет `StoryletDirector` через публичный API), компилятор
уже в клиенте, `GameRenderer` изначально принимает `root: HTMLElement`. iframe не экономит
ничего, но добавляет кросс-origin проблему dev-серверов и postMessage-протокол.

Что делается:

- Из `game/src/main.ts` извлекается `game/src/embed.ts`:
  `mountStory(root, bundle, { seed?, snapshot?, persist: false, onSnapshot?, onTrace? })` —
  сегодня вся сборка зашита в невыносимый наружу `launchStorylet`.
- `game/package.json` получает exports; клиент подключает `link:../game` (прецедент — story_core).
- Монтирование в **Shadow DOM**: единственный реальный конфликт — глобальный `style.css` игры
  (`:root`, `*`, `html/body`) — инжектится внутрь ShadowRoot и не дерётся с Industry-токенами.
- `persist: false` — превью не пишет сейвы в localStorage студии (та же origin!).

**Инвариант «превью = релиз»:** окно ест ровно тот бандл, что производит `buildStoryletBundle`,
и исполняет его ровно тем движком, что уедет в standalone. Бандл — постоянный дешёвый
автопересобираемый артефакт (компилятор идемпотентен и работает в браузере): изменился
артефакт → бандл пересобрался → превью готово к перезапуску. Различие превью и релиза — только
обвязка, и это надо не потерять: **строгий режим** («как релиз») переключателем — без заглушек
прозы и плейсхолдеров ассетов, чтобы не воспитать «в превью работает, в сборке падает».

Возможности окна (паттерны индустрии, применённые к нашему движку):

- **Позиция = seed + лог выборов.** Правка исходника посреди прохождения → тихая пересборка
  бандла, перезапуск с нуля и промотка по логу (паттерн Inky) — автор остаётся «на месте».
  Если лог стал невалиден (правка изменила доступные выборы) — не молчаливый рестарт,
  а видимая точка расхождения: «дошли до дня 3, дальше история изменилась».
- **Перемотка.** `DirectorSnapshot` полностью сериализуем, включая состояние ГПСЧ — снапшот на
  каждой смене сцены, откат детерминирован (паттерн Ren'Py rollback). Кликабельный транскрипт:
  клик по прошлой реплике = откат туда.
- **Играть отсюда.** Из «Структуры»: кнопка на бите/слоте — доигрывание политикой из
  `simulatePolicies` до ближайшего хаба перед точкой (честная инициализация состояния,
  а не warp с пустыми переменными), дальше руками.
- **Инспектор состояния.** Живая панель: отношения, флаги, слот/фаза, seed. Seed виден и
  управляем: «переролл» / «зафиксировать» (ГПСЧ уже seeded — не хватает только UI).
- **Трассировка режиссёра.** На каждой точке выбора — все кандидаты пула: вердикт каждого
  guard-а (какой предикат срезал), салиенс-скор, ярус, жребий/не жребий. `SelectionTrace` уже
  существует для `?gudebug` — его надо отдать в `onTrace` и отрисовать панелью. Это прямой
  ответ на «непонятно, что происходит внутри» — теперь и в рантайме.
- **Баг-репорт одной строкой:** seed + лог выборов — воспроизводимая позиция, вставляется в
  заметку режиссёру на юнит.
- Здесь же крутится **SelectorConfig** — «ручка режиссуры»: изменение конфига селектора не
  требует перегенерации (едет в бандл бесплатно), превью + сравнение прогонов симуляции —
  естественное место, где её настраивают и проверяют.

Анти-грабли (из чужих шишек): превью играет только на deep-copy состояния и никогда не мутирует
проектные сторы (канонический провал Unity ScriptableObject); dev-поблажки (заглушки прозы,
плейсхолдеры ассетов) существуют только вне строгого режима и всегда видимы бейджем.

## 9. Ветки, брекеты, канвас — явные ответы

- **Ветки** (`branchAssignment`, дорожки «Чертежа») — часть «Структуры истории»: дерево
  показывает развилки, превью получает переключатель ветки (форс выбора на развилке), QA-политики
  прогоняют все ветки, ведомость считает готовность по веткам.
- **Брекеты** (positive/neutral/negative) — свойство артефакта прозы юнита: три тейка одной
  сцены; «Сценарий» читается в одном брекете (как сейчас `scriptBracket`), превью показывает
  фактический брекет по состоянию отношений.
- **Канвас-редактор** (`pages/main`) — вне конвейера. Он не зона и не этап: остаётся отдельным
  инструментом свободного наброска (или честно выводится из продукта — решение владельца).
  Конвейер на него не ссылается.

## 10. Хранилище (предпосылка, без которой не взлетит)

Слепая зона всех трёх концептов — квота localStorage (~5–10 МБ), в которую уже упирается
`gu-narrative-state` v11. Тейки, журнал прогонов, реестр релизов туда физически не помещаются.

- Артефакты, тейки, лента, релизы → **IndexedDB** (проектно-скоупленные базы по образцу
  `projectScope`); в localStorage остаются только лёгкие сторы (бриф, UI, реестр проектов).
- `image_server`: проектный префикс в путях, GC отвергнутых тейков и осиротевших файлов
  удалённых проектов; сегодняшняя плоская папка `images/` — техдолг с дедлайном.
- Батчи генерации живут в памяти сервисов и умирают при рестарте (404 → пересчёт) — политика
  ретраев и бюджет попыток становятся полем колл-щита, а не сюрпризом.
- Контракт на **фактический usage** от text_gen/image_gen — серверная работа, после которой
  смета из «≈» становится фактом (`resolveActualCost` — заготовленная точка).

## 11. Фундамент / переделать / выбросить

**Фундамент (не трогать, на этом стоим):** story_core как единственный исполнитель +
детерминизм и снапшотируемость (seed, `DirectorSnapshot`); идемпотентный компилятор
`buildStoryletBundle` + `stubMissingProse`; `draft/committed` + `effectiveScalar/effectiveMap`;
каскад `dirtyStages`; транспорт `runBatch` + `pendingBatch`-реаттач; best-of retry с
`previousIssues`; `imageFingerprint` + reconcile (образец для всех отпечатков); `qaSeeds`
(маршрут issue → стадия-владелец); `SelectionTrace` + `formatGuard/formatEffect`;
`validateStoryBundle` + CLI-хвост `build:game`; `projectScope`-многопроектность; инвариант
Selection → Inspector; derive-архитектура студии; симметрия capture ↔ apply префабов;
генерация брифа (§3, зона 0): каталог `briefFields` как единая точка истины,
`computeBriefGaps` → `briefFill` с фидбек-ретраем, `mergeGeneratedBrief` только в пустые поля,
`briefHintParse` как прообраз адресных заметок режиссёру, «авто»-поля через
`resolveBrief`/`resolveScale`.

**Переделать:** `runLog` → типизированная шина событий; прогресс `N/9` → план по позициям;
три медиа-хука → дорожки оркестратора с персистентным статусом; `hierarchyModel` → две панели;
префаб-копирование → `CastRef` + версионные снапшоты; `commitCalendarRun` → позонный коммит;
`computeExportGate` → честные гейты релиза; `prefabProvenance`-этикетка → провенанс на артефакте.

**Выбросить:** адаптер `deriveLegacyOutline` (рудимент снесённого графа — медиа-хуки пересадить
на прямые входы); дубль промпт-кода в `useBulkCharacterGeneration`/`useRegeneratePoses`;
правило «QA не запускался = гейт открыт»; невидимый до финала draft; вечно-disabled кнопки
перегенерации в инспекторах; молчаливое выпадание юнитов без прозы из бандла.

**Миграция:** narrativeStore v12 навешивает `{ownership, fingerprint}` на существующие Record-ы;
всё существующее получает `approved + fresh` (оплаченное не протухает от самой миграции);
`.guproj` получает версию формата, старые файлы читаются без кастинга (роли = `manual`).

## 12. Дорожная карта внедрения

Порядок выбран так, чтобы каждый инкремент был ценен сам по себе и не оставлял продукт
в полу-мигрированном состоянии. Первые три — чистая видимость и превью, они не трогают модель данных.

Нулевой инкремент уже сделан вне этой таблицы: **генерация брифа** (§3, зона 0) — пробелы
вместо формы целиком, «авто»-поля, директивы из заметок, смета на кнопке, откат. Она служит
образцом законов 2 и 5 в малом масштабе и задаёт транспорт (batch-стадии text_gen, фидбек-ретрай,
merge-только-в-пустое), который переиспользуют №1 и №4. Её долг перед конвейером — оркестрация
в компоненте вне общего Web Lock (осознанное исключение, см. §3) — гасится при №8.

| # | Инкремент | Закрывает | Суть |
|---|---|---|---|
| 1 | **Стеклянный прогон** | боль 3 (~80%) | Типизированная лента поверх runLog; раши (draft в derive-вьюхи); колл-щит из `dirtyStages` + `costModel`; медиа-статусы переезжают из useState в стор. Модель данных не меняется. |
| 2 | **Превью** | требование 5 | `game/src/embed.ts` + exports + `link:../game`; Shadow DOM; авто-бандл; панель состояния; seed-UI; `SelectionTrace`-панель. Самостоятельная ценность с первого дня. |
| 3 | **Две панели** | боль 2 | Разрез `hierarchyModel` на «Пайплайн» и «Структуру» — derive-only, дёшево. |
| 4 | **Точечная регенерация** | боль 4 (ядро) | Две оси статусов; заметки → `previousIssues` per-itemKey; контракт стабильных ключей + reconcile; включение кнопок инспекторов; превью последствий правки; редактор каркаса зоны 1. Первая миграция persist. |
| 5 | **Кастинг по ссылке** | боль 1 | prefabStore v2 (версии-снапшоты); `CastRef` в брифе; снапшоты в `.guproj`; кастинг-стол. |
| 6 | **Тейки и хранилище** | предпосылки | IndexedDB; история попыток; галерея тейков; проектный скоуп image_server + GC. |
| 7 | **Релизы** | продакшен-хвост | Release-сущность; честные гейты; реестр релизов; diff lockfile-ов. |
| 8 | **Автопилот и чекпоинты** | глубина руления | Порционная генерация с паузами; позонный коммит; континуити-QA стыков; фактический usage с сервера. |

Перемотка (rewind в превью), «Играть отсюда», строгий режим — довески к №2 по мере готовности
снапшот-инфраструктуры; play-from-here зависит также от политик доигрывания (`simulatePolicies` готов).

Порядок сверен с предпосылкой §10 о квоте localStorage: **лента (№1) — новая сущность и с
первого дня пишется в IndexedDB**, а не в localStorage; метаданные статусов и заметки (№4) —
килобайты в существующем сторе; всё тяжёлое (история тейков, снапшоты релизов) появляется
только вместе с №6. До №6 ретеншн попыток — сегодняшний (последняя), и документ этого
не стесняется.
